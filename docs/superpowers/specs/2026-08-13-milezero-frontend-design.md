# MileZero 심사 데모 프런트엔드 설계

## 목적

심사위원이 로그인 없이 하나의 모바일 우선 웹앱에서 MileZero의 핵심 가치를 직접 경험한다. 홈 진입 후 GPS 집계값으로 배송 마찰이 자동 감지되고, 배송기사의 불편을 묻는 중립 질문, 멀티모달 제보, 개인정보 제거, 독립 검증, 다음 기사 가이드, 도움 피드백과 추가 포인트까지 한 흐름으로 연결한다.

## 제품 원칙

- 원본 GPS 좌표는 브라우저 밖으로 보내지 않고 집계 특징만 API에 전달한다.
- 질문은 기사 책임을 묻지 않고 배송지 시설로 인한 불편과 억울함을 말할 수 있게 한다.
- 개인정보가 포함된 응답은 재질문하지 않고 해당 부분만 제거해 저장한다.
- 제보 등록 즉시 10포인트를 주고, 독립 검증 시 20포인트, 도움 피드백 시 5포인트를 추가한다.
- 실제 API 경로와 합성 데모 경로를 같은 인터페이스로 사용하되 합성 데이터는 화면과 문서에서 명확히 표시한다.

## 정보 구조와 사용자 흐름

### 1. 오늘 배송 홈

- 상단 파란 컨텍스트 탭에 `오늘 배송`과 `다음 배송`을 둔다.
- 현재 배송 카드에 합성 장소명, 차량 유형, 배송 단계와 지오펜스 상태를 표시한다.
- 홈 진입 약 1초 뒤 집계된 GPS 특징으로 `/v1/questions`를 호출한다.
- 마찰이 감지되면 상태 카드와 바텀시트로 질문을 노출한다.
- `데모 다시 보기` 버튼으로 언제든 초기 상태부터 재생한다.

### 2. 중립 질문과 제보

- 서버가 만든 질문과 선택지를 큰 터치 영역으로 표시한다.
- `불편하지 않았어요`는 항상 중립 선택지로 유지한다.
- 문제 선택 뒤 선택형 응답, 2,000자 이하 텍스트, 음성 파일, 사진 파일 중 필요한 것만 추가한다.
- 사진과 음성은 미리보기만 하고 원본은 서버 저장 대상이 아님을 안내한다.
- 최종 CTA는 카카오 T 옐로우를 사용하고 `경험 보내고 10P 받기`로 표현한다.

### 3. AI 처리와 제보 완료

- 제출 중 `응답 이해 → 개인정보 제거 → 운영 지식 구조화 → 후보 저장` 단계를 순차 표시한다.
- 성공 시 기본 10포인트와 추출된 후보 지식을 보여준다.
- 개인정보 발견 시 제거되었다는 안전 안내만 표시하며 추가 입력을 요구하지 않는다.
- 실패 시 바텀시트를 유지하고 재시도할 수 있으며 원본 응답은 브라우저 메모리 안에만 남는다.

### 4. 독립 확인과 다음 기사 가이드

- `다음 배송` 탭은 다른 합성 기사 ID로 `/v1/knowledge`를 조회한다.
- 후보 지식은 `현재도 맞나요?` 카드로 보여주고 `맞아요`와 `정보가 달라요`를 제공한다.
- 확인 후 검증된 지식은 출입구·하역·차량 제한 등 행동 문장과 신뢰도로 보여준다.
- 가이드 사용 뒤 `도움됐어요`와 `정보가 달라요`를 제공하고 도움 피드백 시 제보자 추가 5포인트를 안내한다.

## 시각 시스템

- 첨부된 Kakao T 토큰을 CSS 변수로 옮긴다. 기본 캔버스는 화이트와 뉴트럴 50, 상단 탭은 `#3478F6`, 최종 행동만 `#FAE100`을 사용한다.
- Pretendard를 시스템 한글 폰트 폴백과 함께 사용한다. H1 24/800, H2 18/800, 본문 14/600 기준이다.
- 모바일 컨테이너는 480px, 좌우 14px, 4px 배수 간격, 10~16px 모서리, 최소 44px 터치 영역을 사용한다.
- 아이콘은 Phosphor의 일관된 라운드 벡터 아이콘을 사용하며 플랫폼 이모지는 사용하지 않는다.
- 데스크톱에서는 모바일 앱 셸을 중앙 배치하고 주변에 제품 설명과 개인정보 원칙을 보조 패널로 제공한다.
- `prefers-reduced-motion`을 존중하고 색상 외 텍스트·아이콘으로 상태를 함께 표현한다.

## 기술 구조

- `frontend/src`에 React 19 + Vite 앱을 둔다.
- `api.ts`는 질문, 제보, 지식 조회, 피드백 API를 타입 안전 함수로 캡슐화한다.
- `useDemoJourney`는 화면 상태와 서로 다른 합성 기사 ID를 관리한다.
- UI는 토큰, 공통 primitives, 홈/질문/제보/가이드 기능 컴포넌트로 나눈다.
- Vite 개발 서버는 `/v1`, `/health`, `/ready`를 Fastify로 프록시한다.
- 프로덕션 빌드는 `frontend/dist`에 생성하고 `backend`의 Fastify가 SPA fallback과 정적 자산을 제공한다.
- `MILEZERO_MODE=demo`에서는 인메모리 저장소와 결정적 합성 AI 어댑터로 같은 HTTP API를 실행한다. 기본 모드는 계속 Gemini와 Supabase를 사용한다.

## 오류와 안전 처리

- 네트워크, 4xx, 5xx 오류를 공통 `ApiError`로 변환해 사용자 행동이 가능한 한국어 메시지를 표시한다.
- 지원하지 않는 파일과 8MB 초과 파일은 클라이언트에서 먼저 차단하며 서버 검증을 최종 경계로 유지한다.
- 중복 제출은 동일 idempotency key를 재사용해 포인트와 제보가 중복 생성되지 않게 한다.
- 미디어 Base64는 제출 시에만 생성하고 완료·초기화 시 컴포넌트 상태에서 제거한다.

## 검증 기준

- 컴포넌트 테스트가 자동 감지, 질문, 제보, 검증, 도움 피드백의 상태 전이를 검증한다.
- API 클라이언트 테스트가 헤더, Base64 변환, 오류 매핑을 검증한다.
- 기존 백엔드 테스트와 타입 검사를 모두 유지한다.
- 프로덕션 빌드 후 실제 Fastify 서버에서 홈 HTML과 API readiness를 확인한다.
- 390px 모바일과 1280px 데스크톱에서 브라우저 시각 QA를 수행하고 콘솔 오류·오버플로·접근 가능한 이름을 확인한다.
